# AIPIM Webhook Trigger

The **AIPIM Webhook Trigger** allows you to start workflows automatically based on specific events that occur in **AIPIM** (AI Product Information Management). It enables seamless event-driven automation, helping you react to changes in products, attributes, categories, category trees, and templates in real time.

## How It Works

When a selected event occurs in AIPIM, this trigger activates your workflow and passes the event data as payload. You can configure it by selecting your AIPIM account credentials, the entity type to monitor, the API version, and the specific event types (create, update, delete).

## Use Cases

- **Product Sync**: Automatically sync product updates from AIPIM to your e-commerce platform
- **Data Validation**: Trigger data quality checks when attributes are created or updated
- **Notification System**: Send alerts to teams when categories or templates are modified
- **Analytics**: Track product catalog changes for business intelligence
- **Multi-System Sync**: Keep multiple systems in sync when AIPIM data changes
- **Template Management**: Trigger workflows when product templates are created or updated to ensure consistency across product types
- **Category Hierarchy Sync**: Sync category mappings across multiple systems whenever the category structure changes
- **Variant Tracking**: Monitor product variant relationships and configurations to maintain accurate product listings
- **Bundle Management**: Track parent-child product relationships for bundle updates and inventory management

## Configuration Steps

### 1. Select AIPIM Account
- **Required**: Yes
- **Description**: Choose the AIPIM organization credentials that will authenticate webhook requests and securely connect your workflow to AIPIM.

### 2. Select Event Name
- **Required**: Yes
- **Description**: Choose the specific entity for which you want to listen to events. The available event names are dynamically loaded from your AIPIM account based on the configured webhook events. Common event types include:
  - **Product events**: Product catalog items
  - **Attribute events**: Product attributes and specifications
  - **Template events**: Product templates and configurations
  - **Category events**: Product categories
  - **Category-Mapping events**: Category hierarchy mappings
  - **Relationship-Mapping events**: Product relationships such as bundles and variants
  
  Note: Additional event types may be introduced in the future as AIPIM evolves.

### 3. Select Event Version
- **Required**: Yes
- **Description**: Choose the API version for the webhook events. This ensures the trigger listens to the correct event payload structure.

### 4. Select Events (Multi-select)
- **Required**: Yes
- **Description**: Choose one or more event types you want the trigger to respond to:

**Note**: You can select multiple event types. For example, selecting both "Create" and "Update" will trigger your workflow for both new and modified records.

## Configuration Examples

### Example 1: Product Creation

Monitor when new products are added to AIPIM:

- **AIPIM Account:** My AIPIM Org
- **Event Name:** Product
- **Event Version:** v2
- **Events:** Create

This setup will trigger your workflow whenever a new product is created in AIPIM.

### Example 2: Category Updates

Track all changes to categories:

- **AIPIM Account:** My AIPIM Org
- **Event Name:** Category
- **Event Version:** v1
- **Events:** Create, Update, Delete

This setup triggers the workflow for any category creation, modification, or deletion.

### Example 3: Attribute Management

Monitor attribute lifecycle:

- **AIPIM Account:** My AIPIM Org
- **Event Name:** Attribute
- **Event Version:** v1
- **Events:** Create, Update

This configuration triggers workflows when attributes are created or updated.

## Event Payload Structure

When an event occurs, AIPIM sends a webhook payload to Boltic. You can access this data in subsequent workflow steps using `{{payload}}`.

The webhook payload has the following structure:
- **event**: Metadata about the webhook event
- **company_id**: Your AIPIM organization ID
- **payload**: The actual entity data (product, attribute, category, etc.)

## Accessing Payload Data

In your workflow activities, you can reference webhook data using template variables:

### Common Fields (Available in All Events)

- **`{{payload.event.name}}`** - The entity type (product, attribute, template, category, category-mapping, relationship-mapping)
- **`{{payload.event.type}}`** - The action (create, update, delete)
- **`{{payload.event.version}}`** - The API version used (e.g., "1" or "2")
- **`{{payload.event.created_timestamp}}`** - Unix timestamp when the event occurred
- **`{{payload.event.id}}`** - Unique event identifier
- **`{{payload.company_id}}`** - Your AIPIM organization ID
- **`{{payload.payload}}`** - Full entity data object

### Event-Specific Fields

**Product Events:**
- **`{{payload.payload.sku}}`** - Product SKU
- **`{{payload.payload.title}}`** - Product title
- **`{{payload.payload.selling_price}}`** - Selling price
- **`{{payload.payload.mrp}}`** - Maximum retail price
- **`{{payload.payload.brand}}`** - Brand ID
- **`{{payload.payload.category}}`** - Category array
- **`{{payload.payload.images}}`** - Image array

**Attribute Events:**
- **`{{payload.payload._id}}`** - Attribute ID
- **`{{payload.payload.name}}`** - Attribute name
- **`{{payload.payload.code}}`** - Attribute code
- **`{{payload.payload.type}}`** - Attribute type (e.g., "Decimal", "Short Text")
- **`{{payload.payload.action}}`** - Action field (create/update/delete)

**Template Events:**
- **`{{payload.payload._id}}`** - Template ID
- **`{{payload.payload.name}}`** - Template name
- **`{{payload.payload.attributes}}`** - Attributes array
- **`{{payload.payload.groups}}`** - Attribute groups array
- **`{{payload.payload.action}}`** - Action field (create/update/delete)

**Category Events:**
- **`{{payload.payload._id}}`** - Category ID
- **`{{payload.payload.name}}`** - Category name
- **`{{payload.payload.code}}`** - Category code
- **`{{payload.payload.action}}`** - Action field (create/update/delete)

**Category-Mapping Events:**
- **`{{payload.payload.code}}`** - Mapping code
- **`{{payload.payload.name}}`** - Mapping name (e.g., "Electronics > Mobiles > Smartphones")
- **`{{payload.payload.mapping}}`** - Hierarchy mapping array
- **`{{payload.payload.action}}`** - Action field (create/update/delete)

**Relationship-Mapping Events:**
- **`{{payload.payload.type}}`** - Relationship type (parent-child or variant)
- **`{{payload.payload.parent}}`** - Parent SKU (for parent-child relationships)
- **`{{payload.payload.childs}}`** - Child products array
- **`{{payload.payload.variants}}`** - Variants array (for variant relationships)
- **`{{payload.payload.action}}`** - Action field (create/update/delete)

### Safe Access Patterns

Since delete events have minimal payloads, always check for field existence:

**Example 1 - Safe product title access:**
```
{{#if payload.payload.title}}
  Product: {{payload.payload.title}}
{{else}}
  Product SKU: {{payload.payload.sku}}
{{/if}}
```

**Example 2 - Conditional logic based on event type:**
```
{{#if (eq payload.event.type "delete")}}
  Deleted {{payload.event.name}} with ID: {{payload.payload._id}}
{{else}}
  {{payload.event.type}} {{payload.event.name}}: {{payload.payload.name}}
{{/if}}
```

## Workflow Examples

### Example 1: Product Creation Notification

**Scenario**: When a new product is created in AIPIM, send a Slack notification and create a record in Google Sheets.

1. **Trigger**: AIPIM Webhook (Event Name: Product, Events: Create)
2. **Activity 1**: Send Slack message
   - Channel: #product-updates
   - Message: "New product created: `{{payload.payload.title}}` (SKU: `{{payload.payload.sku}}`)"
3. **Activity 2**: Add row to Google Sheets
   - Spreadsheet: Product Catalog
   - Row data: SKU (`{{payload.payload.sku}}`), Title (`{{payload.payload.title}}`), Price (`{{payload.payload.selling_price}}`)

### Example 2: Template Update Notification

**Scenario**: When a product template is created or updated, send an email notification to the product team.

1. **Trigger**: AIPIM Webhook (Event Name: Template, Events: Create, Update)
2. **Activity 1**: Send Email
   - To: product-team@company.com
   - Subject: "Template {{payload.event.type}}: `{{payload.payload.name}}`"
   - Body: "Template `{{payload.payload.name}}` was {{payload.event.type}}d in AIPIM. Description: `{{payload.payload.description}}`"
3. **Activity 2**: Log to Database
   - Table: template_audit_log
   - Fields: template_id (`{{payload.payload._id}}`), action (`{{payload.payload.action}}`), timestamp (`{{payload.event.created_timestamp}}`)

### Example 3: Bundle Management with Inventory Sync

**Scenario**: When a relationship-mapping event occurs (bundle created/updated), sync inventory levels across all child products.

1. **Trigger**: AIPIM Webhook (Event Name: Relationship-Mapping, Events: Create, Update)
2. **Activity 1**: Filter (only process parent-child relationships)
   - Condition: `{{payload.payload.type}}` equals "parent-child"
3. **Activity 2**: Loop through child products
   - Array: `{{payload.payload.childs}}`
   - For each child:
     - Update inventory system with SKU (`{{item.sku}}`) and quantity (`{{item.quantity}}`)
4. **Activity 3**: Send Slack notification
   - Channel: #inventory-updates
   - Message: "Bundle `{{payload.payload.relationship_name}}` {{payload.event.type}}d with {{payload.payload.childs.length}} child products"

## Notes

- You must configure and verify your **AIPIM organization credentials** before using this trigger
- Event versions (v1 vs v2) may have different payload structures — consult AIPIM API documentation
- The trigger passes detailed event payloads to the workflow, accessible via `{{payload}}`
- Multiple event types can be selected to trigger on create, update, and delete in a single configuration
- Ideal for building event-driven automations such as syncing data, updating systems, or sending notifications when AIPIM data changes

## Best Practices

1. **Test with Sample Data**: Use the "Test" feature to see sample payloads before deploying
2. **Handle All Event Types**: If selecting multiple events, ensure your workflow logic handles create, update, and delete appropriately
3. **Version Consistency**: Use v2 for new integrations to leverage the latest features
4. **Error Handling**: Add error handling activities to manage failed webhook processing
5. **Filter Events**: Use Boltic's filter activities to process only relevant events based on specific criteria
6. **Handle Partial Payloads**: Delete events typically have minimal payloads containing only identifiers - ensure your workflow handles these gracefully by checking for field existence before accessing nested properties
7. **Version-Specific Logic**: For product events, be aware that both v1 and v2 versions exist with identical payload structures - choose the version that matches your AIPIM configuration
8. **Event Type Awareness**: Use `{{payload.event.type}}` to determine the action (create, update, delete) and build conditional logic accordingly for different event handling

## Troubleshooting

### Webhook Not Triggering

- Verify your AIPIM credentials are valid
- Check that the webhook is properly registered in AIPIM
- Ensure the selected event types match the actual events occurring
- Confirm network connectivity between AIPIM and Boltic

### Incorrect Payload Data

- Verify the event version (v1 vs v2) matches your AIPIM configuration
- Check AIPIM API documentation for the expected payload structure
- Use the Test feature to inspect sample payloads

### Multiple Triggers Firing

- Review your event type selections — selecting multiple events will trigger for each
- Consider using filters to process only specific events
- Check for duplicate webhook configurations

### Missing Fields

- Some event types have minimal payloads, especially delete events which typically contain only identifiers
- Ensure your workflow safely accesses optional fields using conditional logic (e.g., check if `{{payload.payload.title}}` exists before using it)
- Different event types have different structures - for example, product events don't include an `action` field in the payload while attribute, template, category, category-mapping, and relationship-mapping events do

### Unexpected Payload Structure

- Different event types (product, attribute, template, category, category-mapping, relationship-mapping) have different payload structures
- Verify you're processing the correct event type by checking `{{payload.event.name}}`
- Delete events have minimal payloads compared to create/update events
- Product v1 and v2 have identical payload structures - only the `event.version` field differs
